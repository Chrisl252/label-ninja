# Label Ninja: redesign audit and preservation map

Reviewed October 5, 2026. This is a design review artifact, not a release. The source inspected is `C:\Code\label-ninja.com\lane-site-improve-20261004`, including the prepared affiliate changes. The baseline screenshots below show the live site's design. Source metadata and the live screenshot baseline are separate evidence; the local affiliate candidate has not been approved for publication.

## What needs to change

Label Ninja has useful tools, but the site makes a new visitor read product copy and navigate a flat list before choosing a job. The redesign should begin with “What are you trying to print?” and take the visitor straight to a working tool or a symptom-specific fix.

| Finding | Observed evidence | Design response |
| --- | --- | --- |
| The identity is weak and inconsistent. | Near-black chassis tokens, a blue accent, gray secondary text and generic panels dominate the site. Thermal stock details exist, but do not lead the experience. `public/css/tokens.css:10–35`. | Make paper, ink, label edges and one safety accent the core identity. Use a legible light default and an equally considered dark mode. |
| The intended typography does not consistently arrive. | Tokens name Barlow Condensed, Barlow and IBM Plex Mono; the root document does not load their web fonts. The guide hub does load them. There are no local font-face declarations. `public/css/tokens.css:49–51`; `public/index.html:52–66`; `public/guides/index.html:28–30`. | Load the selected type family consistently, with deliberate fallbacks. Verify actual loaded fonts in the browser. |
| Tools compete with navigation and explanatory copy. | The main navigation lists individual tools. Studio modes add another tool-tab row. The homepage hero offers two selected workflows instead of a task picker that covers all five tools. `public/index.html:74–103`. | Group navigation into Tools, Labels & Sizes, Printers and Guides. Put the job picker above the fold and preserve fast return to a current draft. |
| The homepage is more specific than a generic centered template, but still undersells the product. | It already has an asymmetric text/label composition and four real SVG sample labels. `public/index.html:95–119`; `public/assets/home-*.svg`. | Keep the useful subject matter. Replace the passive illustration with a task-led preview or workbench entry that shows what the visitor can accomplish. |
| Printer comparison is a shopping table rather than a decision workflow. | The embedded table has “Consider when / Printer / What to check / Shop” columns and six candidates, but no filters or selected comparison state. `public/index.html:569–618`. | Start with use case and connection needs; show exact-model limits, “good for / skip if” explanations and a mobile comparison treatment. Verify specs before adding them. |
| Repeated document sections make different jobs feel the same. | Guides and landing pages share a heading, paragraph, table/steps and next-tool pattern. | Give tools a workbench, troubleshooting pages a symptom/decision path, and comparisons a shortlist. Reuse tokens and components without forcing every page into one layout. |
| Trust exists in policy copy but is not immediately useful. | The studio and converter have different account, upload and retention behavior. `public/privacy.html:91–107`. | Put a truthful privacy/account statement beside each tool's primary action. Use Chris's supplied warehouse experience without inventing tests, metrics or certifications. |
| Existing diagrams deserve better placement. | Guides already include original label transformations and explicitly labeled generic print-setting drawings. `public/guides/8-5x11-shipping-label-to-4x6.html:123`. | Put the relevant setting or dimension diagram beside the step it explains. Do not replace it with unrelated stock photography. |

No Lighthouse, Core Web Vitals, revenue lift, ranking lift or measured conversion claim was generated by this audit. Color contrast, actual font loading and responsive behavior must be verified on the approved implementation.

### Exact current stock presets

Editor presets, in inches: **2.25×1.25, 2×1, 3.5×1.125, 1×1, 2×0.75, 1×0.5, 2.3125×4, 4×6, 4×3, 3×2, 2×2, 2.25×4** (`public/js/app/presets.js:4–16`). Whatnot supports 1×0.5, 2×1 and 3×2; bin output is 4×6 or 6×4. FNSKU output is fixed 2×1.

**Not implemented:** ZPL input/rendering or ZPL errors; PNG download; a user-controlled 203/300 DPI selector; 4×4 or 1×2.125 presets; CSV import. These are feature proposals, not visual controls that can be shown as working. The converter's internal fallback uses 300 DPI when vector PDF embedding is unavailable (`sources.js:100–112`); that is not a selectable printer-DPI setting.

## Privacy, account and affiliate gates

- **Converter privacy:** files are read and PDFs are constructed in the browser. Converter modules have no label-upload `fetch` call. Only sanitized settings persist under `ln.labelcrop.v1`; file contents are not stored there (`label-crop/prefs.js:1–15,28–37`, `output.js:15–28`).
- **Studio privacy:** export sends label text, barcodes, dimensions and images to the server; saved projects persist their contents. Finished PDFs remain downloadable for seven days (`app/exporter.js:118–143`; `privacy.html:91–107`). Never use a site-wide “nothing leaves your device” badge.
- **Draft continuity:** switching views preserves the in-memory draft within the tab. The resume link is not durable autosave (`workspace-navigation.js:1–18`). A redesign must not destroy a draft when visiting a guide or home.
- **Free-tool contract:** keep tools free, with no pricing, paid quotas, billing UI or Stripe. Studio export/save still requires an account. The server's abuse guards remain 200 pages/export and 30 exports/hour/user (`src/limits.js:5,17,20`).
- **Affiliate candidate:** preserve the prepared Amazon tag, sponsored/noopener attributes, nearby disclosure and compatibility copy. Do not alter ordinary manufacturer/source links into shopping links. Check with `npm run check:affiliates`.
- **Release gate:** `config/affiliates.json` currently records `websiteListed: false`; the release checker blocks publication until the site listing is verified. An active tracking tag does not prove website approval, purchases or commission. No account changes or deployment are authorized by a design-direction review.
- **Product claims:** do not invent hands-on tests, universal stock compatibility, printer specifications, customer counts, reviews, Amazon prices or conversion improvements. Explicitly identify untested decisions and exact model variants.

## SEO and implementation preservation plan

1. Preserve all ten indexable URLs, canonical targets, descriptive titles, metadata and meaningful content. Use the captured [source baseline](evidence/seo-before.json) to review intentional changes. It is a local-source snapshot, not a live indexing report.
2. Retain existing guide-to-tool and related-guide links. Give important tools, printer decisions and new approved pages discoverable text links. Do not turn crawlable documents into empty client-only shells.
3. Each visible view needs one meaningful H1 and one main landmark. Distinguish homepage source headings from app headings mounted by JavaScript; the baseline records both without pretending all are simultaneously visible.
4. Keep structured data tied to visible content. Preserve current types where appropriate; do not add fictional reviews/ratings or unsupported claims. Inspect actual rendering and validate the approved schema.
5. Keep sitemap entries canonical and indexable, with truthful modification dates. Add new pages only after their content and route work exist. Preserve real 404s and legacy redirects.
6. Build the chosen identity as tokens and shared components, then apply job-specific layouts across home, tools, guides, printer decisions, account/reset, policies and 404. Keep source modular.
7. Verify desktop/mobile layout, actual font loading, keyboard/focus states, touch editing, crop/rotate behavior, preview-to-PDF size, project reopening, auth/reset/export flows, and affiliate checks. Existing test success does not certify physical printing or live production.
8. Show the complete approved candidate in Chrome and obtain explicit release approval before publishing. No silence-as-approval path.
