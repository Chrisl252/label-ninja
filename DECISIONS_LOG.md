## 2026-09-02: HOTFIX — every deep link in production was a 500 (missing `[assets] binding`)

- **The defect (live, revenue-path):** `wrangler.toml`'s `[assets]` block declared `directory`, `html_handling` and `not_found_handling` but **never declared `binding`**, so `env.ASSETS` was `undefined` at runtime. Cloudflare serves an exact asset match before invoking the Worker, so `/`, `/privacy`, `/css/*` and `/js/*` were fine — but **every non-asset path fell through to the Worker**, hit `env.ASSETS.fetch(request)` in `serveStatic()`, threw `TypeError: Cannot read properties of undefined (reading 'fetch')`, and returned the generic `{"error":{"code":"internal_error"}}` **500**. Confirmed in production on the brick-3 release (`b639a3d9`): `/pricing`, `/reset`, `/reset?token=`, `/billing`, `/account`, `/foo` — all 500. The SPA fallback branch inside `serveStatic` was dead code: it can never run, because the first line throws.

Every password-reset email (`/reset?token=`) dead-ended the same way. So did any shared deep link and any typo'd URL. ## 2026-08-31: Brick 4 — Stripe billing backend + canceled-paid-through entitlement fix

- **Entitlement semantics fix (correctness bug in live code):** spec rule "access remains through the paid-through date after normal cancellation" is now real. `src/entitlements.js` `isProActive` = `status active|trialing` → pro; `canceled|past_due` → pro only while `paid_through > now`; `incomplete`/`unpaid`/null never grant. The `plan === 'pro'` term was **dropped from the predicate** — `plan` is now a synced display column derived FROM the predicate (billing's `applySubscriptionState` imports `isProActive` to set it; reading it back would be circular). No Stripe-key dependency: predicate is pure status+paid_through. B2 bonus path (plan='pro' + status='active' via d1) still passes.
- **`paid_through` units:** Stripe `current_period_end` is unix SECONDS; the column stores MILLISECONDS (consistent with every other timestamp here). `applySubscriptionState` converts `×1000`. Handles both `sub.current_period_end` and `items[0].current_period_end` (newer API versions).
- **`src/billing.js` (370 lines, Stripe via REST fetch — no SDK, no new deps):** `GET /api/config/pricing` (module-level per-isolate `Map` price cache, `expand[]=product`; unkeyed → `{"ok":true,"configured":false}`; keyed-but-fetch-fails → `configured:false, error:"price_fetch_failed"`; keyed-but-price-ids-missing → `error:"prices_not_configured"` — real Stripe data only, never invented strings), `POST /api/billing/checkout` (401→503→400 invalid_plan guards; ensure-customer with `metadata[user_id]`; success `/billing?checkout=success`, cancel `/pricing`; upstream failure → 502 `stripe_upstream_error`), `POST /api/billing/portal` (400 `no_customer` without a bound Stripe customer). Non-2xx Stripe responses throw `{status, stripeCode}`; logs carry the error CODE only, never the body (account data).
- **Webhooks (`POST /api/webhooks/stripe`):** manual Stripe-scheme verification — parse `t` + every `v1`, `|now−t| ≤ 300s`, HMAC-SHA256(secret, `${t}.${body}`) hex, constant-time compare (reuses db.js `timingSafeEqual`); any failure → 400 `invalid_signature`. Missing `STRIPE_WEBHOOK_SECRET` also 400s (nothing can verify — safe by default). Idempotency: `INSERT OR IGNORE INTO webhook_events` claims the event id; redelivery → `{"ok":true,"duplicate":true}` and STOP — **refinement:** if the stored result starts with `error:`, the claim is released and the event reprocesses (otherwise Stripe's retries would short-circuit as duplicates and an errored event could never land; spec's "return 500 so Stripe retries" only works with this release-on-error). Handler error → `result='error: <code>'` + HTTP 500 so Stripe retries. Success stores `result` and returns it in the 200 body.
- **Handlers:** `checkout.session.completed` binds `stripe_customer_id` when null; if the user already has a DIFFERENT customer → `customer_mismatch_ignored` and NO relink (anti-hijack); subscription fetch failure degrades to `customer_bound_subscription_fetch_deferred` 200 (the accompanying `customer.subscription.*` event always carries the state — failing delivery over the fetch would cause a pointless retry storm). `customer.subscription.updated|deleted` resolves user by `stripe_subscription_id`, else by customer when exactly one user is bound, else `no_matching_user`. `invoice.payment_failed` sets `past_due` (access continues via paid_through) and re-syncs plan via the predicate. Unknown types → `ignored`.

## 2026-08-31: SaaS pivot brick 2 — server-side PDF export engine + atomic 10-use metering

- **Reservation-then-generate pattern:** `POST /api/export` enforces the free entitlement with a single atomic statement — `INSERT INTO usage_ledger ... SELECT ... WHERE (granted + admin deltas − export count) > 0`. `stmt.changes === 0` → 402 `free_limit_reached` with `upgrade_url:"/pricing"` inside the error object; the client's spec is never deleted. ## 2026-08-26: Physical Print Contracts, Local Artwork, and Production Hosting

- **Decision:** Every generator sets an explicit physical CSS page size before printing. Warehouse bins use 4x6 portrait pages; Whatnot stock is selectable and defaults to 1x0.5 landscape.
- **Reason:** Browser viewport sizing and printer-driver defaults produced oversized or clipped labels. Exact CSS inches keep one complete label on each physical sheet when the matching driver paper, zero margins, and 100% scale are selected.
